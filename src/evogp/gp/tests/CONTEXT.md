# `src/evogp/gp/tests/` — the pytest suite of the torch-free evoxc GP stack
## Intent
Regression gate for `src/evogp/gp/`: it pins the encoding contract, the operator layer, the problem/evaluator numerics, the driver on BOTH routes (host numpy and device-resident iree), plus the two import properties the stack exists for (no torch, no `evoxc` at import time).
It is a separate suite from `src/evogp/tests/` (the torch stack's suite) and is not collected by it; both must pass.
## API Surface
- `conftest.py` — sets `EVOGP_EVOXC_BACKEND=numpy` (hermetic, no IREE compile on a device box by default) and puts `src` on `sys.path`, both at import time before any `evoxc` use.
  A device test therefore has to pass `backend="iree"` plus an explicit `evoxc.Device` itself; the pin is not a device ban.
- `gp_operator_support.py` — the shared (non-test) helpers of the operator and device suites: `SAFE_CONFIG`/`RICH_CONFIG` and their function sets, `channel_arrays`, `recompute_sizes`, `assert_well_formed` (validation plus a bottom-up subtree-size recomputation), the independent list-slicing splice oracle and `assert_row_equal`, plus the device gate and transport helpers `usable_device_kind` (`"rocm"`/`"cuda"` or `None`, probed without compiling anything), `DEVICE_SKIP_REASON`, `is_device_tensor` and `to_host` (the explicit `to(evoxc.Device("cpu", 0))` download, because a device payload's `.numpy()` refuses).
- `test_gp_stack_encoding.py` — 33 cases: static shape/dtype/`-inf`-fitness/key invariants, `row_length`/`live_mask` consistency, zero padding and zero function-node payloads, well-formedness (depth bound, arity-derived subtree sizes, opcode legality, variable-index range), key determinism (same key ⇒ identical population, new key ⇒ different), key-tensor vs seed equivalence, `pop_size` sources (`(GPTreeConfig, GPConfig)` pair), graph memoization, `output_len > 1` rejection, degenerate function sets (unary-only, single level, all leaves), the leaf/const/variable distribution against the configured probabilities, the legacy-triple round-trip (both directions, plus `OUT_NODE` rejection), the `validate_channels` rejection matrix (including rank-3 channels and unequal 1-D rows), and the acceptance of the single-individual form (three 1-D channel rows) by `validate_channels`/`row_length`/`live_mask`.
- `test_gp_stack_config.py` — 26 cases: derived tables (cdf, depth schedule, padded layout, arity/type tables), frozen/hashable/`replace`, the `using_funcs` spellings, weighted cdfs, zero-weight functions, deterministic const drawing, the validation matrix, and the `GPConfig` rules.
- `test_gp_stack_operators_selection.py` — the three modes against closed-form distributions, not goldens: tournament's rank probabilities `((n-r)**k - (n-r-1)**k) / n**k`, uniform sampling of an all-equal population, `rank_probabilities`' linear mass, roulette's shifted-fitness mass with zero weight for `-inf` rows, plus index range/dtype and the malformed-knob rejections.
- `test_gp_stack_operators_crossover.py` — the splice against the independent list oracle (`reference_splice_row`), the `max_nodes` overflow path, gate-0 verbatim copies, position draws inside the live length, and the host entry point's shape contracts.
- `test_gp_stack_operators_mutation.py` — the three kinds (`point`/`subtree`/`hoist`) stay well-formed, keep arity at `point`, never mutate a gated-off row, and the probability knobs behave (`0` = identity, `1` = every row).
- `test_gp_stack_operators_variation.py` — one whole generation in one graph: shape/dtype stability, ten chained generations stay well-formed, every selection × mutation combination, the rich function set, an all-`-inf` population, offspring-only behaviour, rate `0` degenerating into pure selection, and the returned key.
- `test_gp_stack_problem_contract.py` — hand-built trees pinning the evaluator's *semantics* (operand order, the `if` select, protected/loose edges, the ±1 comparison clamps, the `max`/`min` NaN asymmetry, the maximize-and-negate convention, the fresh-writable output, the `VAR` bounds error, the non-finite → `-inf` mapping and the memory-bounded row chunking) plus the problem layer's `predict`/`loss`/`evaluate`/`__call__` contract and data validation.
- `test_gp_stack_problem_parity.py` — the numpy evaluator against the plain-torch oracle `test/oracle/reference_eval.py` (the same dev-only oracle `test_gp_stack_problem_engine.py` uses: `<repo>/test/oracle` inserted on `sys.path`, skipped naming that path when absent) on populations drawn by `init_population` (so the padded growth and the pre-order scatter are under test too), across the arithmetic / ternary / comparison / transcendental function sets, several tree depths, row widths and `input_len` values, summarized in one deviation table.
- `test_gp_stack_problem_engine.py` — the third oracle: the dev-only, correctly-rounded reference evaluator `test/oracle/reference_eval.py` (off `PYTHONPATH`; imported by a `sys.path` insert of `<repo>/test/oracle` and skipped, naming that path, when the checkout has no dev tooling) driven through `to_legacy_triple`, comparing `batch_forward_from_rows` to `evaluator.predict` (non-finite pattern exact, values within 1e-5 relative — measured 0.0) and `sr_fitness_from_rows` to `SymbolicRegression.loss` / `.evaluate` (1e-5 relative — measured ≤1.34e-7, absolute 6.1e-5).
- `test_gp_stack_problem_graph.py` — the in-graph variant: `predict_graph`/`sr_fitness_graph` equal the host evaluator, one memoized graph per shape (hit/miss counters in `graph_cache_stats`), the loss reduction inside the graph, and `clear_graph_cache`.
- `test_gp_stack_workflow_step.py` — the driver's single generation: same static shape/dtypes and well-formedness, elite rows bit-identical (pooling included) and carrying their real fitness while the offspring are `-inf` -- gathered by the VARIATION graph, whose `elite_count`/`elite_index` path is what the driver only forwards -- `elite_count=0`, an all-`-inf` population, the advanced key, `evaluate` called exactly once per generation on a concrete `GPState` (never a symbolic tensor), the NaN → `-inf` sanitation, and the error contract (wrong fitness length/rank, non-callable objective, population/config mismatch, a bare `GPConfig`).
- `test_gp_stack_workflow_run.py` — the loop: `generations=0`/`1` semantics, the monotone per-generation best, the elite surviving a generation, one `evaluate` call and one callback entry per generation, same-key reproducibility vs different-key divergence, the reported best channels reproducing `best_fitness` when fed back AS IS -- a tuple of three 1-D rows is read as a population of one -- (synthetic objective and a real `SymbolicRegression`, plus `validate_channels`/`predict`/`to_legacy_triple` on that form), a `CustomLoss` instance driving a run through `__call__`, a bare `GPTreeConfig` + `pop_size`, the `generations` validation matrix, a fitness-contract break failing the run, a short `smoke.run_smoke` improvement, the aggregate `cache_stats()`/`clear_cache()`, the driver names in a clean subprocess (`PYTHONPATH=src` only, no evoxc/torch), and `apply_variation`/`apply_crossover` leaving the submodules importable.
- `test_gp_stack_device_driver.py` — 19 cases, DEVICE-GATED (skips cleanly without `iree` or a visible device): `init_population`/`init_gp` put every leaf of the state on the device and generate the same generation-0 population as the host run; `variation` on a device state reproduces the numpy generation BITWISE (offspring-only, with `elite_count` and with an explicit `elite_index`); the in-graph elite ranking obeys the host tie rule (`np.argsort(-fitness, kind="stable")`, lowest index wins) and a NaN can never become an elite; one device `step` reproduces the numpy `step` while taking TWO graph runs with **zero** readbacks and zero channel downloads (monkeypatched `readback_fitness`/`encoding._as_numpy` counters, with a positive control proving the instrumentation live); `run` reads back exactly one fitness vector per evaluated generation and downloads the channels only for the generation-0 validation and the final `best_channels` (`validate=False` drops the first); the device trajectory matches numpy inside 1e-5 with `result.state` still device-resident; `GraphEvaluator` equals the host `SymbolicRegression` (numpy backend bitwise, iree ≤1e-5) and accepts host rows; and the package/cache surface exposes the device pieces.
- `test_gp_stack_device_convergence.py` — 2 cases, DEVICE-GATED: a real 18-generation SR run (pop 150, 256 rows, 32-node trees, the `smoke` problem) on the device path, asserting real improvement, agreement with the numpy trajectory at `atol=1e-5`, a replayable best tree and a device-resident final state; ~9 s, three iree compiles dominate.
- `test_gp_stack_device_fused.py` — 36 cases, DEVICE-GATED on `usable_device_kind` + `fused_eval.interop_available` + `fused_eval.fused_available` (and on torch/triton, resolved with `find_spec`/`importorskip`, never at module scope): the skip gate itself; `export_to_torch` declining a host tensor / numpy array / bare triple / non-tensor with a message naming the host path, rejecting a contradicting `device_kind`, and refusing an export whose metadata disagrees with the evoxc tensor (a monkeypatched `torch.from_dlpack` returning a reshaped view); a sharing (not copying) export for all three channels, proven by mutating the torch view (visible through the evoxc tensor, same `data_ptr` on a second export); the return direction as a torch write into an exported evoxc buffer that `variation` then consumes (the elite rows carry exactly the written values), plus the evaluator's persistent fitness buffer (same handle across calls, sized per population) and the `out=` destination that replaces the copy (the loss entry point writes bitwise-identical values into a caller buffer it returns unchanged, the value entry point fills the kernel's `(pop, rows, out_len)` buffer and returns a squeezed view for `per_row=True`, the route is observed handing the kernel its exported `evoxc` buffer, and a non-tensor / wrong-shape / wrong-dtype / non-contiguous / `requires_grad` / contradicting-`out_device` destination is a `ValueError`); `_legacy_triple_device` bitwise-equal to `encoding.to_legacy_triple` for a fresh population, after five chained `variation` calls (stale cells included, asserted non-zero) and for a hand-built padded population (stale cells and a fully padded row zeroed); the host route for host channels and for the three 1-D rows of one individual, recorded as `last_route == "host"`; a mid-call `InteropUnavailable` falling back to the host route with `last_fallback` naming it (device route proven attempted, positive control afterwards); - `test_gp_stack_purity.py` — 26 cases (7 plain test functions plus the source grep parametrized over the subtree's 19 `*.py` modules): a source grep that every module of the subtree (excluding `tests/`) is free of `import torch` / `from torch` / `import evox` / `from evox`; a clean-subprocess check that `import evogp.gp` works with `PYTHONPATH=src` alone and pulls in neither torch, `evox` nor `evoxc`; a clear-error check when `evoxc` is missing at call time; and the table invariants over `evogp._tables` / `evogp.gp._constants` (positional `Func` / `FUNCS_NAMES` / `FUNC_ARITY` / `FUNC_TYPE`, the limits and `NType` markers, `MAX_OUT_LEN` / `OUT_NODE`, the re-export being the same objects, and the table module containing no import line at all).
## Constraints
- numpy evoxc backend for everything but the three DEVICE-GATED modules, small sizes (pop ≤ 2 048, `max_nodes` ≤ 64), and no timing loops — device measurement belongs to `measure_generation.py` / `DEVICE_LOOP.md`.
- A device test gates on `gp_operator_support.usable_device_kind()` and skips (never fails) when it returns `None`; it must pass `backend="iree"` and an explicit `evoxc.Device` itself, because `conftest.py` pins the numpy backend.
- `test_gp_stack_device_fused.py` gates on the interop and fused probes on top of that (`fused_eval.interop_available(kind)` and `fused_eval.fused_available()`), because the device-native fused route additionally needs torch, triton, the DLPack protocol and a writable `TRITON_CACHE_DIR`.
- Torch may be imported here (the dev-only oracle `test/oracle/reference_eval.py` is written in it), never in the subtree's own modules; the oracle modules use `pytest.importorskip` so a torch-less box — or one without the repo's dev tooling — skips instead of failing, and the fused device module keeps torch out of its module scope (pinned by its own `ast` check).
- Tests must not assume execution order: every layer memoizes graphs process-wide (`evogp.gp.clear_cache()` is the reset, and `tests/test_gp_stack_encoding.py` and the driver tests rely on it).
- The driver tests use a deterministic synthetic objective (`-size[:, 0]`, "shorter trees win") for the contract properties and a small real `SymbolicRegression` only where numerics matter, so the suite stays in seconds.
## Known coverage gaps
- No test feeds a population whose padding (cells past `size[:, 0]`) carries non-zero garbage to any evaluation entry point — `evaluator.predict`, `predict_graph` / `sr_fitness_graph`, `graph_eval.GraphEvaluator`, `fused_eval.sr_fitness_fused_channels`; the suite's only garbage-padding fixture (`test_gp_stack_device_fused.py::_PADDING_POPULATION`) is used for the device legacy conversion alone.
- `OUT_NODE` rejection is pinned at `predict` (`test_gp_stack_problem_contract.py::test_out_node_tagged_opcodes_are_not_implemented`), at the legacy bridge (`test_gp_stack_encoding.py::test_legacy_bridge_rejects_multi_output_tags`) and at `FusedDeviceEvaluator` (`test_gp_stack_device_fused.py::test_an_out_node_tagged_opcode_raises_not_implemented`); `predict_graph` / `sr_fitness_graph` and `graph_eval.GraphEvaluator` have no such case, and `init_population` is pinned only through `output_len > 1`.
- The fused route's non-finite sanitization is only exercised on all-finite populations, never with a tree that actually produces a NaN (`test_the_device_route_hands_the_kernel_its_exported_buffer` asserts "finite or -inf").
- The elite ranking's large-`k` `argsort` fallback (`variation._ARGSORT_ELITE_BREAK_EVEN` 50, or `elite_count == pop_size`) has no test; `GPConfig` rejects `elite_count >= pop_size`, so only an operator-level call with pop > 51 could reach it.
- Nothing asserts a caller's `GPState` is left unmodified by `variation` / `step`, nor that a retained `FusedDeviceEvaluator` fitness tensor is invalidated by the next call (the reuse test compares two calls on the same state).
- Channel dtype and non-contiguity, Python-list channel forms, and an all-constant population are untested; non-contiguity is covered only for the kernel's `out=` destination.

## Notes for Agents
- Run: `EVOXC_DISABLE_LOCATIONS=1 PYTHONPATH=src:/root/evoxc /tmp/rocvenv/bin/python -m pytest src/evogp/gp/tests -q` → 309 passed / 36 skipped (345 collected) in ~43 s on a device box; the three DEVICE-GATED modules (`test_gp_stack_device_*`) hold 57 of those cases (2 + 19 + 36) and skip where `iree`, a visible device, torch/triton, or evoxc's native DLPack device export is missing (the 36 `test_gp_stack_device_fused.py` cases are the skips on this box), so a box without a device runs the remaining 288 (a few torch-gated cases in the problem modules may skip there too).
- The `subprocess` purity tests re-invoke `sys.executable` with `PYTHONPATH` overridden; keep them independent of the ambient `PYTHONPATH` (that is the whole point).
- A new module in `src/evogp/gp/` is automatically covered by the source-grep test (it globs the directory), so a stray `import torch` fails without any test edit.
- Convergence is asserted only loosely on the host (a material improvement over generation 0 on a 64 × 30 × 300-cell run), because the exact trajectory is a property of the RNG stream and of the operator constants, not of the driver; the device module asserts its own short trajectory against the numpy one instead.
- Nothing here compares against the TORCH stack's fitness numbers: that comparison is the measurement harness's (`src/evogp/gp/measure_generation.py`, report `DEVICE_LOOP.md`), where the two trajectories differ by construction (different RNG, selection and mutation wiring).

## Rule pins: non-finite fitness and the tie rule (both lanes)
`test_gp_stack_operators_variation.py` carries `test_a_non_finite_fitness_can_never_become_an_elite` (parametrized over `NaN` and `+inf`: the elite slots must come from the FINITE rows and the recorded elite fitness is the sanitized value), `test_a_non_finite_fitness_cannot_win_a_tournament` (rates 0 → the offspring ARE the two parent draws, so a `+inf` row must never appear) and `test_the_elite_tie_rule_prefers_the_lower_row_index` (a flat fitness vector ranks `0, 1, 2`).
`test_gp_stack_operators_selection.py::test_rank_mode_breaks_ties_towards_the_lower_row_index` pins the same tie rule on the selection side, by its FREQUENCY vector in row order (the older flat-fitness test compares the sorted set, which cannot see a flip).
`test_gp_stack_device_driver.py::test_a_non_finite_fitness_can_never_become_a_device_elite` is parametrized over `NaN` and `+inf` too, so the in-graph sanitizer is pinned on the DEVICE lane, not only on numpy.
