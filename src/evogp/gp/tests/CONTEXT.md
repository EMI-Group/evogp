# `src/evogp/gp/tests/` — the pytest suite of the torch-free evoxc GP stack
## Intent
Regression gate for `src/evogp/gp/`: it pins the encoding contract, the operator layer, the problem/evaluator numerics and the driver, plus the two import properties the stack exists for (no torch, no `evoxc` at import time).
It is a separate suite from `src/evogp/tests/` (the torch stack's suite) and is not collected by it; both must pass.
## API Surface
- `conftest.py` — sets `EVOGP_EVOXC_BACKEND=numpy` (hermetic, no IREE compile on a device box) and puts `src` on `sys.path`, both at import time before any `evoxc` use.
- `gp_operator_support.py` — the shared (non-test) helpers of the operator suite: `SAFE_CONFIG`/`RICH_CONFIG` and their function sets, `channel_arrays`, `recompute_sizes`, `assert_well_formed` (validation plus a bottom-up subtree-size recomputation), the independent list-slicing splice oracle and `assert_row_equal`.
- `test_gp_stack_encoding.py` — 31 tests: static shape/dtype/`-inf`-fitness/key invariants, `row_length`/`live_mask` consistency, zero padding and zero function-node payloads, well-formedness (depth bound, arity-derived subtree sizes, opcode legality, variable-index range), key determinism (same key ⇒ identical population, new key ⇒ different), key-tensor vs seed equivalence, `pop_size` sources (`(GPTreeConfig, GPConfig)` pair), graph memoization, `output_len > 1` rejection, degenerate function sets (unary-only, single level, all leaves), the leaf/const/variable distribution against the configured probabilities, the legacy-triple round-trip (both directions, plus `OUT_NODE` rejection), the `validate_channels` rejection matrix (including rank-3 channels and unequal 1-D rows), and the acceptance of the single-individual form (three 1-D channel rows) by `validate_channels`/`row_length`/`live_mask`.
- `test_gp_stack_config.py` — 27 tests: derived tables (cdf, depth schedule, padded layout, arity/type tables), frozen/hashable/`replace`, the `using_funcs` spellings, weighted cdfs, zero-weight functions, deterministic const drawing, the validation matrix, and the `GPConfig` rules.
- `test_gp_stack_operators_selection.py` — the three modes against closed-form distributions, not goldens: tournament's rank probabilities `((n-r)**k - (n-r-1)**k) / n**k`, uniform sampling of an all-equal population, `rank_probabilities`' linear mass, roulette's shifted-fitness mass with zero weight for `-inf` rows, plus index range/dtype and the malformed-knob rejections.
- `test_gp_stack_operators_crossover.py` — the splice against the independent list oracle (`reference_splice_row`), the `max_nodes` overflow path, gate-0 verbatim copies, position draws inside the live length, and the host entry point's shape contracts.
- `test_gp_stack_operators_mutation.py` — the three kinds (`point`/`subtree`/`hoist`) stay well-formed, keep arity at `point`, never mutate a gated-off row, and the probability knobs behave (`0` = identity, `1` = every row).
- `test_gp_stack_operators_variation.py` — one whole generation in one graph: shape/dtype stability, ten chained generations stay well-formed, every selection × mutation combination, the rich function set, an all-`-inf` population, offspring-only behaviour, rate `0` degenerating into pure selection, and the returned key.
- `test_gp_stack_problem_contract.py` — hand-built trees pinning the evaluator's *semantics* (operand order, the `if` select, protected/loose edges, the ±1 comparison clamps, the `max`/`min` NaN asymmetry, the maximize-and-negate convention, the fresh-writable output, the `VAR` bounds error, the non-finite → `-inf` mapping and the memory-bounded row chunking) plus the problem layer's `predict`/`loss`/`evaluate`/`__call__` contract and data validation.
- `test_gp_stack_problem_parity.py` — the numpy evaluator against the plain-torch oracle `evogp.tests.reference_eval` on populations drawn by `init_population` (so the padded growth and the pre-order scatter are under test too), across the arithmetic / ternary / comparison / transcendental function sets, several tree depths, row widths and `input_len` values, summarized in one deviation table.
- `test_gp_stack_problem_engine.py` — the third oracle: the shipped engine (`Forest.batch_forward` / `Forest.SR_fitness` with the numpy `evoxc` backend) driven through `to_legacy_triple` and compared to the host evaluator; torch/evoxc/CUDA absence skips it cleanly instead of failing.
- `test_gp_stack_problem_graph.py` — the in-graph variant: `predict_graph`/`sr_fitness_graph` equal the host evaluator, one memoized graph per shape (hit/miss counters in `graph_cache_stats`), the loss reduction inside the graph, and `clear_graph_cache`.
- `test_gp_stack_workflow_step.py` — the driver's single generation: same static shape/dtypes and well-formedness, elite rows bit-identical (pooling included) and carrying their real fitness while the offspring are `-inf`, `elite_count=0`, an all-`-inf` population, the advanced key, `evaluate` called exactly once per generation on a concrete `GPState` (never a symbolic tensor), the NaN → `-inf` sanitation, and the error contract (wrong fitness length/rank, non-callable objective, population/config mismatch, a bare `GPConfig`).
- `test_gp_stack_workflow_run.py` — the loop: `generations=0`/`1` semantics, the monotone per-generation best, the elite surviving a generation, one `evaluate` call and one callback entry per generation, same-key reproducibility vs different-key divergence, the reported best channels reproducing `best_fitness` when fed back AS IS -- a tuple of three 1-D rows is read as a population of one -- (synthetic objective and a real `SymbolicRegression`, plus `validate_channels`/`predict`/`to_legacy_triple` on that form), a `CustomLoss` instance driving a run through `__call__`, a bare `GPTreeConfig` + `pop_size`, the `generations` validation matrix, a fitness-contract break failing the run, a short `smoke.run_smoke` improvement, the aggregate `cache_stats()`/`clear_cache()`, the driver names in a clean subprocess (`PYTHONPATH=src` only, no evoxc/torch), and `apply_variation`/`apply_crossover` leaving the submodules importable.
- `test_gp_stack_purity.py` — 9 tests: a source grep that every module of the subtree (excluding `tests/`) is free of `import torch` / `from torch` / `import evox` / `from evox`; a clean-subprocess check that `import evogp.gp` works with `PYTHONPATH=src` alone and pulls in neither torch, `evox` nor `evoxc`; a clear-error check when `evoxc` is missing at call time; and the constants parity against `evogp.tree.utils` and `evogp.tree.generation._func_tables`.
## Constraints
- numpy evoxc backend only, small sizes (pop ≤ 2 048, `max_nodes` ≤ 64), and no timing loops — device measurement belongs to the benchmarking task.
- Torch may be imported here (it is the reference oracle), never in the subtree's own modules; the constants-parity tests use `pytest.importorskip` so a torch-less box skips instead of failing.
- Tests must not assume execution order: every layer memoizes graphs process-wide (`evogp.gp.clear_cache()` is the reset, and `tests/test_gp_stack_encoding.py` and the driver tests rely on it).
- The driver tests use a deterministic synthetic objective (`-size[:, 0]`, "shorter trees win") for the contract properties and a small real `SymbolicRegression` only where numerics matter, so the suite stays in seconds.
## Notes for Agents
- Run: `EVOXC_DISABLE_LOCATIONS=1 PYTHONPATH=src:/root/evoxc /tmp/rocvenv/bin/python -m pytest src/evogp/gp/tests -q` → 267 passed in ~18 s.
- The `subprocess` purity tests re-invoke `sys.executable` with `PYTHONPATH` overridden; keep them independent of the ambient `PYTHONPATH` (that is the whole point).
- A new module in `src/evogp/gp/` is automatically covered by the source-grep test (it globs the directory), so a stray `import torch` fails without any test edit.
- Convergence is asserted only loosely (a material improvement over generation 0 on a 64 × 30 × 300-cell run), because the exact trajectory is a property of the RNG stream and of the operator constants, not of the driver.
