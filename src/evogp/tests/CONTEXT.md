# `src/evogp/tests/` — pytest suite for the ETL-based (CUDA-free) EvoGP engine
## Intent
Automated verification of EvoGP's rewritten evaluation engine: GP trees are evaluated through ETL's "true jit" (host-side decode of the population tensors into a static structure → `etl.build_cached` specialization → shared `etl.CompileCache`), and generation/mutation/crossover are plain-torch tensor ops.
These tests are the regression gate: an independent plain-torch reference evaluator plus randomized/adversarial equivalence tests, operator-invariant tests, public-API compatibility tests, a small convergence smoke, and the numeric cross-check against the frozen outputs of the deleted CUDA kernels.
## Contents
- `reference_eval.py` — independent plain-torch oracle (slow, obviously-correct) implementing the original `_process_node` semantics; must NOT import the engine it verifies.
  Public entries (`__all__`): `decode_row(row_value, row_type, row_size, out_len=1, check=True)` (`:261`), `flatten(node)` (`:339`), `forward_tree(tree, x, out_len=1, multi_output=None)` (`:478`), `forward_from_rows(node_value, node_type, subtree_size, inputs, out_len=1)` (`:560`), `batch_forward_from_rows(node_value, node_type, subtree_size, x, out_len=1)` (`:582`), `sr_fitness_from_rows(...)` (`:601`), plus `arity_of`/`is_function_kind`.
  Cost per tree: one Python-level torch op per node over the `(N,)` data vectors (reverse-prefix stack walk, correctly-rounded float32 via float64 intermediates) — O(nodes) Python work and O(nodes) transient `N`-wide tensors per row, O(pop × nodes × N) per population; CPU-oriented and slow, use it for correctness spot checks, never for timing.
- `test_equivalence.py` — randomized + adversarial engine-vs-reference equivalence through the public `Forest`/`Tree` API; also owns the golden-fixture discovery, schema dispatch and every golden comparison (see "Golden fixtures" below).
  Multi-output (`output_len > 1`, out-nodes) is part of the engine's contract and its two equivalence tests RUN against the engine; the `multi_output_supported()` probe before them skips ONLY on a design-level refusal (`NotImplementedError`) and turns a wrong shape / wrong value / any other exception into a test FAILURE (a broad `except Exception` there would hide engine bugs behind a skip; the guard's two branches are pinned by `test_multi_output_guard_skips_only_design_level_refusals`).
- `test_operators.py` — generation validity/reproducibility + mutate/crossover splice invariants and silent-copy edge cases (int32 index tensors).
- `test_api_compat.py` — import surface (incl. the `CustomLoss` re-export), indexing/pickle/concat/sympy (incl. constant-only tree repr/sympy), execute_mode string compatibility.
- `test_combined_forward.py` — input-dict shape-contract regression for `CombinedForest.forward`/`batch_forward` and `CombinedTree.forward`: hand-checked single-point/batch values, batch==per-row equivalence, column-form equivalence and the exact rejection messages (12 tests).
- `test_mujoco_problem.py` — `MujocoProblem` lazy-import binding (module globals `jax`/`jnp`/`registry`/`MjxEnv` after `import_jax_based_package`) plus a construction smoke that skips at the third-party `mujoco-warp`/CuDNN boundary.
- `test_convergence_smoke.py` — tiny end-to-end symbolic-regression run; asserts best fitness improves.
- `perf_probe.py` — standalone ETL build/run economics probe (numpy vs iree); NOT a pytest module (`__main__`-guarded, never collected).
  It imports `etl`/numpy directly and re-implements the engine's meta-programming pattern locally (module-level `@etl.defn _step(x, tree)` at `:294` + nested-tuple static trees composed at trace time) — it never imports `evogp`, so it measures the ETL pattern, not `evogp.tree.etl_engine` itself.
  Measures per tree (wall-clock ms): cold `build_cached` miss, warm `etl.run` (device-only and host-readback), cache-hit `build_cached`, trace/lower/compile/load breakdown, the `ETL_DISABLE_LOCATIONS=1` delta (one subprocess per setting), bounded process/thread-pool build throughput, and extrapolated pop=200/1000 per-generation cost (`extrapolate` at `:883`, model `pop × warm_run + #distinct × cold_build`).
  ETL API surface it drives: `etl.CompileCache` (`:144`), `etl.core.Device("cpu"|"cuda", i)` (`:146`/`:465`), `etl.TensorSpec((N, 2), etl.float32)` (`:490`), `etl.build_cached(_step, spec, tree, cache=..., backend=..., device=..., target_backends=["cuda"], opt_level="O1")` (`:501`), `etl.run(exe, x, tree)` (`:525`), `etl.trace`/`etl.lower`/`etl.compile`/`etl.load` (`:598`-`:607`), `etl.from_numpy` (`:494`).
  CLI (`parse_args` at `:1106`): `--quick` (effective default) / `--full` (presets QUICK/FULL at `:154`/`:164`), `--backends numpy|iree` (default both), `--n` (default 100,1000; `--full` appends 10000), `--trees`, `--seed` (default 20240), `--device-index`, `--skip-parallel`, `--skip-locations`, `--json-out PATH`, plus hidden child-mode args `--child-locations`/`--reps`; always writes the JSON report under `$TMPDIR/evogp_etl_perf_probe_<ts>.json` and prints it between `JSON-BEGIN`/`JSON-END` (human tables from `print_tables` at `:927`).
  Semantics: NO `assert`/PASS-FAIL/threshold checks anywhere — failed sections are recorded in the JSON `errors` dict and the exit code stays 0 (unlike repo-root `test/etl_jit_probe.py`, which exits 1 on FAIL); the parity block (`:1235`-`:1261`) reports max|diff| vs numpy but never asserts it.
  Coverage boundary: the stage breakdown is fixed at N=1000 on `trees[0]` (`:1269`), the locations child at N=1000 (`:638`) and the parallel section at N=1000 on `trees[:5]` (`:1288`/`:1306`), so `--n` only affects sections 1-3 + tables; it never measures `evogp.tree.etl_engine`'s `decode_population` cost, the per-call input cast/host→device copy or the output assembly/transfer — pop=200/1000 generation costs are model extrapolations (`extrapolate`, `:883`), not measurements.
- `goldens/` — data only: 7 committed `.npz` golden fixtures (`01_random_single_out` … `07_deep_skew`) in the **engine schema** plus `README.md` documenting each case and the format. Loaded by `test_equivalence.py`; not a Python package.
## How to run
From the repository root (`ETL_DISABLE_LOCATIONS=1` speeds tracing up ~4× and is what the counts below were measured with; the project venv has torch 2.6.0+cu124 and 8 CUDA devices, so `DEVICE` defaults to cuda in the equivalence/smoke tests):
- Whole suite: `ETL_DISABLE_LOCATIONS=1 PYTHONPATH=src /mnt/local-ssd/bchuang/evox/.venv/bin/python -m pytest src/evogp/tests -q` → **308 passed, 4 skipped, 6 warnings in ~1m55s** (verified: 115.0 s; 312 collected). The 4 skips are stable and none of them is a multi-output skip: `test_api_compat.py`'s pygraphviz/`to_png` guard (`:381`) and the two "`forward` exposes no `execute_mode`" guards (`:466`, `:489`), plus `test_mujoco_problem.py`'s construction smoke (`:72`, third-party `mujoco-warp`/CuDNN boundary; its binding test passes).
- Fast subset (skips the heavy differential file): append `--ignore=src/evogp/tests/test_equivalence.py` → **119 passed, 4 skipped in ~9 s** (verified: 8.5 s); `test_equivalence.py` dominates the full run (verified: 189 passed in 113.1 s on its own).
- Golden cross-checks only: append `-k golden` (6 tests) → **6 passed in ~6.3 s**.
- Single file: replace the path (`-x` stops at the first failure).
- Write-free run (worktree stays clean): add `-p no:cacheprovider` and `PYTHONDONTWRITEBYTECODE=1`.
- Perf probe: `/mnt/local-ssd/bchuang/evox/.venv/bin/python src/evogp/tests/perf_probe.py --quick` (~36 s) or `--full` (~2m20s), per the module docstring's A6000 measurements (no `PYTHONPATH=src` needed — it imports only `etl`/numpy, never `evogp`).
## Constraints
- No test may depend on a compiled extension (there is none any more) and the reference path must not require a GPU.
- `reference_eval.py` stays independent: no imports from `evogp.tree.etl_engine` (it is the oracle the engine is checked against).
- RNG semantics intentionally differ from the old kernels (torch-RNG sampling, distribution-equivalent, not bit-exact) — tests must not assert exact sampled values; the legacy fixtures are therefore used as frozen *inputs* to the engine, never as RNG transcripts.
- Semantics authority: `../tree/ENGINE_SPEC.md` (durable spec extracted from the kernels) and `../tree/CONTEXT.md`; for the legacy capture also `<repo-root>/test/goldens/README.md`.
- The suite contains NO timing/performance assertions (`perf_counter`/`time` appear only in `perf_probe.py`); engine wall-clock work belongs in the standalone probe, not in pytest.
## Numeric contract pinned by these tests (engine implementations must preserve)
- Engine-vs-oracle comparisons use global `RTOL = ATOL = 1e-4` (`test_equivalence.py:176-177`); NaN/±inf placement is asserted first (`torch.equal` on the masks + inf signs, `:388-402`) and only the finite entries are then compared (`assert_close_with_placement`, `:377-409`).
- Stricter-than-1e-4 engine checks: comparison ops must be bit-exact (`test_comparison_operators_are_exact`, `:1013-1035`, `exact=True` → rtol=atol=0 at `:407`), a perfect SR fit must be exactly 0.0 (`:1138-1143`), and the unread row tail must be bit-invariant via `assert_same_bits` (`torch.equal` after NaN/±inf canonicalization, `:604-613`, `:1198-1219`; tail junk tested as CONST/BFUNC/TFUNC types).
- `test_api_compat.py` cross-call tolerances: forward modes rtol=1e-4/atol=1e-5 (`:482`, `:502`), SR_fitness modes and SR_fitness-vs-MSE magnitude rtol=1e-3/atol=1e-4 (`:415`, `:427`, `:441-443`), batch_forward vs forward rtol=1e-4/atol=1e-5 (`:516`).
- Tests exercise only the public `evogp.tree` API (`Forest`/`Tree`/`GenerateDescriptor`/`MAX_STACK`/`randint`/`NType`, `test_equivalence.py:130`); no test imports `evogp.tree.etl_engine` for evaluation, touches `CACHE`/`cache_stats`/`clear_cache`/`EVOGP_ETL_CACHE_SIZE`, or asserts cache size/hit/miss — the only cache expectations live in `perf_probe.py` (`:507-512`, `:752-753`) and it has zero `assert` statements (failures go to the JSON `errors` dict, exit code 0).
## Golden fixtures
Two fixture sources with **two different schemas**, both optional, both handled by `test_equivalence.py`.
1. **engine schema** — `src/evogp/tests/goldens/*.npz` (7 cases, captured from this engine). One `.npz` per case: `node_value (pop, max_tree_len) f32`, `node_type i16`, `subtree_size i16`, `x (N, input_len) f32`, plus `expected (pop, N, out_len) f32` (checked against `batch_forward`) or `expected_fitness (pop,) f32` + optional `labels (N, out_len) f32` / `use_mse` (checked against `SR_fitness`). Checked by `test_golden_engine_schema_fixtures`.
   Verified shapes: 01 `(16, 64)` rows + `x (32, 2)`; 02 `(24, 4)` + `x (16, 2)`; 03 `(16, 4)` + `x (16, 2)`; 04/05 `(16, 64)` + `x (32, 2)` + `labels (32, 1)`; 06 `(16, 64)` + `x (32, 2)` + `expected (16, 32, 2)` (output_len 2); 07 `(1, 401)` + `x (8, 2)`.
2. **legacy-capture schema** — `<repo-root>/test/goldens/*.npz` (read-only for this node), the frozen outputs of the **deleted custom CUDA kernels**, produced by `test/golden_capture.py` and documented array-by-array in `test/goldens/README.md`. Files: `forest_random.npz` (generation stage), `forward_eval.npz` (tree/forest/batch forward + display strings), `sr_fitness.npz` (all four execute modes × MSE/MAE at forest, tree and `SymbolicRegression` level + the pure-torch path), `training.npz` (12-generation run: descriptors, `initial_forest__*`, `final_forest__*`, `best_tree__*`, `generation_fitness`). Recognized by any `<prefix>__node_value` + `<prefix>__node_type` + `<prefix>__subtree_size` triple (`forest`, `initial_forest`, `final_forest`, `best_tree`).
   Verified shapes: `forward_eval`/`sr_fitness` populations `(64, 63)` + `x (64, 2)`; `forest_random` carries the same `(64, 63)` rows plus `x_small (8, 2)` and the descriptor arrays; `training` `initial_forest`/`final_forest` `(200, 128)` + `datapoints (1000, 2)`, `best_tree (1, 128)`, `generation_fitness (12, 200)`.
Comparison rules, taken from `test/goldens/README.md` ("Recommended comparison tolerances"): floats `rtol = atol = 1e-4` (`LEGACY_RTOL`/`LEGACY_ATOL`), integer/structural/string arrays **exact**, and NaN/±inf **placement** asserted exactly (the `assert_close_with_placement` helper; 3/64 trees in `sr_fitness.npz` are NaN by design). `Forest`/`Tree` objects are rebuilt from the stored rows, so no RNG is involved.
The six golden tests (`-k golden`) and what they check:
- `test_golden_fixture_discovery` — every discovered `*.npz` is classified; nothing here can fail the suite (reporting/robustness only).
- `test_golden_engine_schema_fixtures` — schema 1 above, through `forest.batch_forward(x)` (`:1589`) and `engine_sr_fitness(forest, x, labels, use_mse)` (`:1599`).
- `test_golden_legacy_capture_forward` — `tree_forward` (8 trees), `forest_forward` (64×1), `forest_batch_forward` (64×8×1) and the display strings (`to_infix`/`to_sympy_expr`/`str_tree`), all exact-placement + 1e-4; engine calls `forest.forward` (`:1626`), `forest.batch_forward` (`:1638`), `forest[i].forward(x)` (`:1648`).
- `test_golden_legacy_capture_sr_fitness` — `forest_sr_fitness__<mode>__<mse|nonmse>` (via `Forest.SR_fitness(inputs, labels, use_mse, execute_mode)`), `tree_sr_fitness__*` (`Tree.SR_fitness`) and `problem_evaluate__*` (`SymbolicRegression(datapoints, labels, execute_mode=...).evaluate(forest, use_MSE=...)`) for the four kernel modes plus the pure-torch path (`:1781`-`:1846`).
- `test_golden_legacy_capture_generation` — `forest_random.npz`'s rows/`x`/`labels`/`x_small` are bitwise identical to the evaluation captures (documented) and reproduce `forward_eval.npz`'s `forest_batch_forward` from those rows.
- `test_golden_legacy_capture_training` — the RNG-independent parts: `initial_fitness` from the stored `initial_forest__*` (+ the pipeline's `NaN → -inf` convention), `best_tree` fitness vs the stored final `best_fitness_per_generation`, plus structural invariants.
Fixture policy (do not regress this):
- Fixtures are classified by **array names, never by directory** — the two READMEs invite copying fixtures between directories, and the loader must not feed a file to the wrong schema.
- Foreign/unreadable fixtures and arrays a fixture does not store are reported via `warnings.warn` with an explicit reason (see `_GoldenOutcome`, which also turns a test that compared nothing into a `pytest.skip`) — they never fail the suite and are never silently ignored.
- Deliberate, documented skips surfaced as warnings: regeneration of the legacy generation stage (torch-RNG stream is distribution-equivalent, not bit-identical) and the training trajectory `generation_fitness[1:]` / `final_forest__*` (needs the legacy kernels' exact RNG-consumption order).
- `$EVOGP_GOLDEN_DIR` still prepends an extra scan directory; the two in-repo directories are always scanned.
