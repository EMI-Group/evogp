# `test/benchmark/r2/round3/` — R3 round after the two engine optimization waves

## Intent
Round 3 re-measures the R2 headline configs with the R2 methodology (same harness, flags, fixtures, wiring and seed) to price wave 1 (host-side cuts in `src/evogp/tree/etl_engine.py`) and wave 2 (the dense one-graph evaluator `src/evogp/tree/dense_engine.py`, now the default route for the `iree` backend under the `auto` policy).
The 12 R3 config ids intentionally match their R2 counterparts, so every record diffs directly against the untouched R2 history.
Everything R3 produces lives under this directory; nothing here writes to `../` or to any R2 result directory.
Owned artifacts: the matrix runner, the backend-agreement pre-flight runner, the manifest, the two validators, the round-comparison table generator, the protocol document and `SUMMARY.md`.
A parallel **Arm B** workstream re-measures the nine new-side R3 configs against a *patched ETL checkout* shadowed onto `PYTHONPATH` (`src:/tmp/evogp_etl_patched_51a7141`, read-only); its ids are the Arm A ids with an `armB_` prefix, so every record diffs directly against `results/new/`, and all of its artifacts live under `results/armB/`.

## API surface / routing table
- `run_all.sh` → the 12-config matrix runner (`--group light|iree|iree-spec|all`, `--only`, `--list`, `--dry-run`, `--timeout`); one `bench_gp.py` process per config, results into `results/new/` and `results/legacy/`, `last_run.txt` at the node root.
- `run_agreement_r3.sh` → the six-arm backend-agreement pre-flight runner (numpy / iree / iree+`EVOGP_EVAL_MODE=specialized` × two fixtures); drives the read-only R2 driver `../check_backend_agreement.py`.
- `manifest.txt` → the validator's expectation list (`id <TAB> side <TAB> json path <TAB> stages?`) for all 12 ids; the 9 new-side ids carry the `stages` marker.
- `check_r3.py` → stdlib-only record validator (R3 copy of `../check_r2.py`); `--manifest … --require-stages` is gate (ii).
- `check_agreement_r3.py` → numpy+stdlib numeric gate over the six agreement records: per-fixture npz-identity, `values_sha256`/array integrity, NaN/±inf count equality, `np.allclose(..., rtol=atol=1e-4, equal_nan=True)` for the `numpy→iree` and `numpy→iree_spec` pairs, plus R2-anchor continuity as INFO only; exit 0 = gate PASS.
- `compare_rounds.py` → stdlib-only R2-vs-R3 table generator (eval first-call + warm medians, per-rep training medians with rep0 "churning" / rep1 "fully warm", and the `*_spec` wave-attribution table); `--markdown` for `SUMMARY.md`.
- `compare_rounds_armB.py` → the Arm B companion generator (same tables joined against the Arm B W2 records, the W1 `git show b728466:` snapshots and the Arm B env/stage/fd/b2 blocks) which imports `compare_rounds.py` for every parsing/median rule; `--markdown` for `SUMMARY_armB.md`.
- `selftest_check_agreement.py` / `selftest_compare_rounds.py` / `selftest_compare_rounds_armB.py` → offline self-tests of the checkers and generators (fake records in a temp dir, no GPU, no repo writes).
- `results/new/` and `results/legacy/` → per-config `<id>.json` + `<id>.log` (created by the runner).
- `results/backend_agreement/` → `<stem>.json` + `<stem>_values.npy` + `<stem>.log` for the six arms (skipped by the validator's directory scan by design).
- **Arm B tooling + records** (all under `results/armB/`, every id the Arm A id with an `armB_` prefix):
  - `run_all_armB.sh` → the 9-config Arm B matrix runner (`--group iree-spec|iree|numpy|all`, `--only`, `--list`, `--dry-run`, `--timeout`); one `bench_gp.py` process per config under the same `ulimit`/`flock`/`timeout` order, results into `results/armB/new/`; the ETL shadow is proven per config by the `etl:` line the runner writes into each log header.
  - `manifest_armB.txt` → the Arm B validator expectation list (9 ids, each with the `stages` marker).
  - `run_agreement_armB.sh` + `check_agreement_armB.py` + `selftest_check_agreement_armB.py` → the six-arm Arm B pre-flight and its gate: per-fixture npz identity, `values_sha256`/NaN-count integrity and a HARD same-stem `values_sha256` identity check against `results/backend_agreement/` (Arm A), exit 0 = PASS.
  - `results/armB/new/` → the Arm B records (`<id>.json` + append-only `<id>.log`; a re-run appends a dated block, so several windows stay visible while the JSON keeps only the latest window).
  - `results/armB/backend_agreement/` → the six Arm B pre-flight records + `run_agreement_armB.last_run.txt`.
  - `results/armB/status_<id>.txt` / `status_<id>_w2.txt` → the per-invocation console captures (windows 1…/ W2 companion), `status_check_r3_armB_*.txt` the validator runs.
  - `results/armB/{armB_runlog_section.md,windows.md,etl_import_probe.txt,gate_outputs.md}` → the Arm B run section (mirroring `../../RUNLOG.md`'s format), the per-window contention evidence (`windows.md`), the dated shadow-proof probes (`etl_import_probe.txt`) and the agreement gate evidence.
  - `./SUMMARY_armB.md` (node root) → the Arm B write-up: the R2 / Arm A / W1 / W2 tables (warm medians, compile + fds, stage deltas, env/shadow), the patched-ETL attribution, both gate results and the window/contention caveats.
- `README.md` → the protocol document (scope table, commands, methodology, gates, stage-probe limitation).
- `SUMMARY.md` → the round write-up: the verdict, the R2-vs-R3 tables generated by `compare_rounds.py`, both gate results and the round's caveats.
- `.gitignore` → ignores `last_run.txt` (generated, disposable).

## Constraints
- R2 records (`../../new/results/r2/`, `../../legacy/results/r2/`) and the R2 methodology (`../SPEC.md`, `../README.md`) are read-only: never rewrite them, never add flags or change fixtures to make an R3 number nicer.
- Method is R2: one process per config, `ulimit -n 65536` first, exactly one `flock -w 7200 /tmp/gpbench_critical.lock` per invocation with `timeout` inside it, warm median as the headline with compile/first-call reported separately, stage probe on the new side.
- GPU 6 by default, never GPU 7 (hardware ECC fault); treat medians as ±10 % on this shared box.
- The R2 stage probe patches the specialized engine's call sites only, so a dense-route run may carry an empty/degenerate `stages` block — documented limitation, not a gate failure.
- IREE stays opt-in and explicitly non-primary; `O2`/`O3` are never used, and no IREE number is quotable until the agreement gate passes.
- `last_run.txt` (the matrix runner's id→exit-code table) is generated output — `.gitignore`d, delete freely. The agreement runner's `results/backend_agreement/run_agreement_r3.last_run.txt` is the executed pre-flight's arm→exit-code evidence and stays committed.
- Arm B writes **only** under `results/armB/`: the frozen Arm A directories (`results/new/`, `results/legacy/`, `results/backend_agreement/`, `../../new/results/r2/`, `../../legacy/results/r2/`), `../RUNLOG.md`, `../SPEC.md`, the runner/checker scripts and `manifest_armB.txt` are read-only, and both ETL checkouts (stock and `/tmp/evogp_etl_patched_51a7141`) are read-only. The Arm B agreement gate is contention-independent and is **not** re-run for a timing window.
