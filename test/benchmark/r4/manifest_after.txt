# test/benchmark/r4/manifest_after.txt -- expected artifacts of the R4 after-round
# pure-forward matrix (the same 8 canonical configs as manifest.txt, re-run after the
# frozen-runner code round under the ETL shadow export /tmp/evogp_etl_patched_87c7562).
#
# This file is a MIRROR of manifest.txt: identical ids, identical mode/backend columns,
# identical order (group numpy first, then group iree; pure64_* before pure200_*,
# *_dense_* before *_specialized_*); only the path column points at this round's records
# under results/after/.  manifest.txt itself is the frozen before-round expectation list
# and must never be edited -- both manifests are gated by the same validator.
#
# Format (TAB-separated, one config per line; '#' starts a comment line):
#
#     id <TAB> mode(dense|specialized) <TAB> backend(numpy|iree) <TAB> expected_json_path
#
#   * id / path    the runner (run_pure.sh) derives the id, the tag (UPPER(id)), the args,
#                  the per-config env and the results dir from its own config table; this
#                  file is the VALIDATOR's expectation list.  Keep the two in sync (3-place
#                  sync: the runner's group arrays, its config_spec() case, and this file).
#   * mode/backend check_r4.py verifies `pure.mode_resolved` / `pure.backend` against these
#                  two columns -- i.e. that the record really is the config it claims to be.
#   * new side only: `--task eval-pure` is a new-side measurement (the legacy CUDA checkout
#                  has no separable pure forward and skips with exit 3), so every record here
#                  must carry `side: "new"`.
#
# Every config was run as
#     bench_gp.py --task eval-pure --fixture <64|200-tree fixture> --mode <mode>
#       --backend <backend> --reps 5 --warmup 10 --invocations <100 dense|50 specialized>
#       --e2e-companion 11 --mem-guard-mb 8192 [--max-cold-builds 400 for iree]
#       --output-checksum
# with EVOGP_EVAL_MODE=<mode> in the environment (so the pure route and the --e2e-companion
# route agree) and PYTHONPATH=src:/tmp/evogp_etl_patched_87c7562 (the after-round ETL shadow
# export; every record's `env` block records it, and every `.log` carries an `etl:` identity
# line whose `file=` proves which checkout was imported).
#
# Smoke records (a 3-record plumbing check of the same task, written before the campaign) are
# deliberately NOT manifest ids; they live under results/smoke/ with their own
# manifest_smoke.txt (`--manifest test/benchmark/r4/results/smoke/manifest_smoke.txt`).
