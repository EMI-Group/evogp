# `test/benchmark/r4/` — R4 round: the pure forward measurement (measurement type 2)
## Intent
R4 measures the **internal graph forward pass** (measurement type 2) next to the end-to-end `problem.evaluate(forest)` numbers (measurement type 1) that R1–R3 quote: one "invocation" = one full-population forward on a fixed `x` with `per_row=False`, with the compile-key derivation, the readback, the host row assembly and the fitness reduction excluded. The same process also runs the real end-to-end path (`--e2e-companion K`), so `E2E − pure` prices the per-call host glue + readback on one box, in one window.
The task lives in the shared harness (`../bench_gp.py --task eval-pure`) with its runner/timing core in `../pure_forward.py`; this node owns the round's protocol, runners, manifests, validators, records and write-ups.
The round has two recorded halves: the pre-code-round **before**-baselines and the **after**-round that re-measured them once the frozen runner APIs landed. It also carries its own **type 1 after-round matrix** (14 cells: both backends × `auto` / `dynamic` / `specialized`, plus two stock twins of the headline iree-`auto` cells), run in the same window as the after pure matrix — so before/after and stock/shadow deltas are same-box comparisons.
The legacy CUDA side has no separable pure forward (one fused kernel call per evaluate), so `--task eval-pure` skips cleanly there (`skipped: true`, exit 3) — this node is new-side only.
## API surface / routing table
- `README.md` → the protocol: the two measurement types side by side, what one invocation times/pays/excludes, the `--task eval-pure` flag table, the JSON key glossary, frozen-vs-fallback labeling (incl. the A/B check), commands, GPU/flock rules, file map, and the IREE agreement pre-flight section (both agreement dirs).
- `SUMMARY.md` → **the round's analysis of record**: the after-round verdict block, the before table (§C) and the `frozen-api` after table (§C.2) with the derived observations (§D / §D.2), the 14-cell type 1 after-round section, the agreement verdicts for both dirs (§E), provenance + exact commands (§F, before and after), caveats (§G) and the executed after-round checklist (§H).
- `RUNLOG.md` → the operator log of the executed campaigns: the before window/identity/contention table + STEP 1 pre-flight + STEP 2 matrix (per-rep spreads, cold-construction split) + sanity triage + anomalies + the post-campaign validator addendum, then the **After-round** section (after identity table incl. the ETL-shadow chain, STEP 1 pre-flight, STEP 2 pure matrix, STEP 2b A/B, STEP 3 type 1 matrix, anomalies, committed artifacts with commit shas, final gates).
- `run_pure.sh` → the 8-config matrix runner (`--group numpy|iree|all`, `--only`, `--list`, `--dry-run`, `--timeout`); one `bench_gp.py` process per config, `ulimit -n 65536` first, one `flock -w 7200 /tmp/gpbench_critical.lock` with `timeout` inside, per-config `EVOGP_EVAL_MODE=<mode>`, an `etl:` identity line per log, results into `$NEW_RESULT_DIR` (default `results/`; the after campaign used `results/after/`), `last_run.txt` at the node root (generated, `.gitignore`d). Env overrides: `NEW_PYTHONPATH`, `NEW_RESULT_DIR`, `PURE_EXTRA_ARGS`.
- `manifest.txt` / `manifest_after.txt` → the validator's expectation lists, 4 TAB-separated fields `id / mode / backend / path`, the same 8 ids in runner order (group `numpy` then group `iree`; `pure64_*` before `pure200_*`, `*_dense_*` before `*_specialized_*`); only the paths differ (`results/` before, `results/after/` after).
- `check_r4.py` → stdlib-only validator (`--manifest`, `--require-companion`, positional paths): task/side identity, modes+backend vs manifest, `pure`/`compile` structural completeness, per-rep list consistency (`per_invocation_ms[i] == block_ms[i]/invocations`, recorded summaries == recomputed statistics), the always-valid ordering bounds (`min <= median <= max`, `min <= mean <= max`; the sample-free `min <= median` / `min <= mean` when the per-rep list is unusable), `per_population_evaluate_ms == median_per_invocation_ms`, the two normalizations, and the companion gate; exit 1 on any failure. A directory scan skips `results/smoke/`.
- `run_agreement_r4.sh` → the 6-record IREE agreement pre-flight runner (2 fixtures × `numpy` / `iree` under default `auto` → dense / `iree` + `EVOGP_EVAL_MODE=specialized`), same `ulimit`-first, one-`flock`-per-record, `timeout`-inside discipline; output dir via `--agree-dir` (or `R4_AGREE_DIR`) — default `results/backend_agreement/`, the after round wrote `results/backend_agreement_after/`.
- `check_agreement_r4.py` → the pre-flight gate (python3 + numpy only — no torch, no evogp, no GPU): per record the identity re-hash (fixture sha256 vs the npz, `<stem>_values.npy` vs the JSON's `values_sha256`, count, NaN/±inf), then per fixture the three roles' `values_sha256` equality with an `np.allclose(rtol=1e-4, atol=1e-4, equal_nan=True)` fallback → PASS / PASS-with-note / hard FAIL; same `--agree-dir` / `R4_AGREE_DIR` override; **IREE numbers are quotable only after a PASS\* on the matching window's dir**.
- `run_e2e.sh` + `e2e_manifest.txt` + `check_e2e_r4.py` → the type 1 after-round tooling. `run_e2e.sh` drives `bench_gp.py --task eval64 --eval-reps 25` over the 14 cells (`--group shadow|stock|all`, `--only`, `--list`, `--dry-run`; env `SHADOW_DIR` / `SHADOW_PYTHONPATH` / `STOCK_PYTHONPATH` / `E2E_RESULT_DIR`), one process per cell under the same lock/ulimit/timeout discipline, `--stage-probe` installed; `e2e_manifest.txt` is the 14-cell expectation list (`id / kind / fixture / backend / mode`); `check_e2e_r4.py` is the stdlib-only validator (identity, kind ↔ recorded PYTHONPATH / etl identity, 25-rep structure, timing and normalization checks) → exit 1 on any failure.
- `results/` → the 8 before-records `<id>.{json,log}` (all `complete`, one process per config, exactly `manifest.txt`'s paths, every record `local-fallback:*`).
- `results/after/` → the after-round artifacts: the 8 pure records (`frozen-api:*`, exactly `manifest_after.txt`'s paths), `etl_import_probe.txt` (the ETL-shadow import-precedence + sha-pin evidence), `ab/` (the frozen-vs-fallback A/B arms, the saved `*_output.npz`, `ab_equivalence_report.txt`) and `e2e/` (the 14 type 1 records + logs + the committed `run_e2e_r4.last_run.txt`).
- `results/backend_agreement/` → the 6 before pre-flight records + logs + the raw `<stem>_values.npy` fitness vectors.
- `results/backend_agreement_after/` → the same 6 records for the after round (on the shadow export) + logs + `_values.npy` + the committed `run_agreement_r4.last_run.txt` (which lists only the 4 records of the final, resumed invocation).
- `results/smoke/` → the pre-campaign plumbing records (3 pure smokes: dense-numpy / specialized-numpy / dense-iree + one `eval64` regression control + the legacy clean-skip record) and `manifest_smoke.txt`; deliberately **not** manifest ids.
- `CONTEXT.md` → this file.
## Constraints
- Everything here is new-side and additive: `../SPEC.md`, `../REPORT.md`, `../r2/**`, `../new/check_smoke.py` and every existing task's behaviour are untouched; the harness changes are the `eval-pure` registry/flag/dispatch wiring plus `run_pure`.
- One process per config/cell (the compile cache is per-process), warm/steady-state only: construction is timed separately (`compile`), then `--warmup 10`, then 5 timed blocks. `--reps 1 --warmup 0` is not quotable.
- The pure route (`--mode`) and the companion route (`EVOGP_EVAL_MODE`) are set together by the runner; a single-route config would compare two different routes.
- Never present a `local-fallback:*` record as a frozen-API number (or vice versa): `pure.runner_source` + `compile.path` say which constructor ran, and the two record sets live in different directories (`results/` before, `results/after/` after).
- `--stage-probe` is accepted but never installed for `--task eval-pure` (it would tax the timed loop): `stages` stays `null` there and the measurement lives in `pure`/`compile`/`e2e_companion`. The type 1 `eval64` cells do install it.
- GPU 6 by default, never GPU 7; medians carry the usual ±10–20 % shared-box band; IREE numbers are only quotable after the matching window's backend-agreement pre-flight PASS\*.
- `results/**`, `results/after/**` (incl. `e2e/`, `ab/`, `etl_import_probe.txt`) and `results/backend_agreement{,_after}/**` are **immutable evidence**: read them, never edit, regenerate or re-run in place — the write-ups are derived from the records, never the reverse.
- `../../../src/evogp/**` is read-only from here (the harness must never be the thing that changes the engine it measures).

## Known Issues
- **The frozen construction has no decode/build split.**  The after-records' `compile.build_ms` and `compile.decode_plan_ms` are `null` (the builders *are* the construction — only `construct_total_ms` is recorded), and `cache_hits` is 0 there where the fallback records counted 5 / 16 hits on the specialized numpy routes.  Never reconstruct a split for a frozen record.
- **Frozen vs fallback is a labeling boundary, not an open equivalence question.**  The A/B (`results/after/ab/ab_equivalence_report.txt`) shows equal `output_checksum` digests, byte-identical `.npz` captures and `max|diff| = 0` on all 53 arrays; the remaining caveat is only that the two record sets must never be mixed in one table without the `runner_source` column.
- **The ETL shadow is path-identified only.**  Stock and shadow both report `etl_version=0.1.0` and the same `rev=` (the editable repo's HEAD); identity comes from `file=` / `pythonpath=` in the per-log `etl:` line plus `results/after/etl_import_probe.txt`.  The source branch is deleted and `/tmp` is session-scoped, so those committed artifacts are the surviving evidence.
- **The type 1 after-records were produced in 3 chunks**, so the committed `results/after/e2e/run_e2e_r4.last_run.txt` holds only the last chunk's 4-row table; the 14 JSONs are the record.
- **Two numpy-dense pure cells have companion < pure** (−10.26 / −12.58 ms): shared-box CPU noise on the CPU-bound numpy backend, reported as measured and never smoothed.
- **IREE processes print a `nanobind` reference-counting dump at interpreter teardown.**  Every after-record exits 0 and is `complete`; the dump is not a failed record.
