# `test/benchmark/r4/` — R4 round: the pure forward measurement (measurement type 2)
## Intent
R4 measures the **internal graph forward pass** (measurement type 2) next to the end-to-end `problem.evaluate(forest)` numbers (measurement type 1) that R1–R3 quote: one "invocation" = one full-population forward on a fixed `x` with `per_row=False`, with the compile-key derivation, the readback, the host row assembly and the fitness reduction excluded. The same process also runs the real end-to-end path (`--e2e-companion K`), so `E2E − pure` prices the per-call host glue + readback on one box, in one window.
The task lives in the shared harness (`../bench_gp.py --task eval-pure`) with its runner/timing core in `../pure_forward.py`; this node owns the round's protocol, runner, manifest, validator, records and write-up.
The legacy CUDA side has no separable pure forward (one fused kernel call per evaluate), so `--task eval-pure` skips cleanly there (`skipped: true`, exit 3) — this node is new-side only.
The round's **before-baselines are RECORDED** (2026-09-13, GPU 6) and `SUMMARY.md` is the analysis of record.
## API surface / routing table
- `README.md` → the protocol: the two measurement types side by side, what one invocation times/pays/excludes, the `--task eval-pure` flag table, the JSON key glossary, frozen-vs-fallback labeling (incl. the after-round A/B check), commands, GPU/flock rules, file map, and the IREE agreement pre-flight section.
- `SUMMARY.md` → **the round's analysis of record**: the before-baseline table (8/8), the derived route/backend/scaling/host-glue observations, the agreement verdict, provenance + exact commands, caveats, and the after-round checklist (§H).
- `RUNLOG.md` → the operator log of the executed campaign: window/identity/contention table, STEP 1 pre-flight, STEP 2 matrix (per-rep spreads, cold-construction split), sanity triage, anomalies, committed artifacts, and the post-campaign addendum.
- `run_pure.sh` → the 8-config matrix runner (`--group numpy|iree|all`, `--only`, `--list`, `--dry-run`, `--timeout`); one `bench_gp.py` process per config, `ulimit -n 65536` first, one `flock -w 7200 /tmp/gpbench_critical.lock` with `timeout` inside, per-config `EVOGP_EVAL_MODE=<mode>`, an `etl:` identity line per log, results into `results/<id>.{json,log}`, `last_run.txt` at the node root (generated, `.gitignore`d).
- `manifest.txt` → the validator's expectation list, 4 TAB-separated fields `id / mode / backend / path`, 8 canonical ids in runner order (group `numpy` then group `iree`; `pure64_*` before `pure200_*`, `*_dense_*` before `*_specialized_*`).
- `check_r4.py` → stdlib-only validator (`--manifest`, `--require-companion`, positional paths): task/side identity, modes+backend vs manifest, `pure`/`compile` structural completeness, per-rep list consistency (`per_invocation_ms[i] == block_ms[i]/invocations`, recorded summaries == recomputed statistics), the always-valid ordering bounds (`min <= median <= max`, `min <= mean <= max`; the sample-free `min <= median` / `min <= mean` when the per-rep list is unusable), `per_population_evaluate_ms == median_per_invocation_ms`, the two normalizations, and the companion gate; exit 1 on any failure. A directory scan skips `results/smoke/`.
- `run_agreement_r4.sh` → the 6-record IREE agreement pre-flight runner (2 fixtures × `numpy` / `iree` under default `auto` → dense / `iree` + `EVOGP_EVAL_MODE=specialized`), same `ulimit`-first, one-`flock`-per-record, `timeout`-inside discipline; records into `results/backend_agreement/`.
- `check_agreement_r4.py` → the pre-flight gate (python3 + numpy only — no torch, no evogp, no GPU): per record the identity re-hash (fixture sha256 vs the npz, `<stem>_values.npy` vs the JSON's `values_sha256`, count, NaN/±inf), then per fixture the three roles' `values_sha256` equality with an `np.allclose(rtol=1e-4, atol=1e-4, equal_nan=True)` fallback → PASS / PASS-with-note / hard FAIL; **IREE numbers are quotable only after a PASS\***.
- `results/` → the 8 canonical campaign records `<id>.{json,log}` (all `complete`, one process per config; canonical paths are exactly the manifest's).
- `results/backend_agreement/` → the 6 pre-flight records + logs + the raw `<stem>_values.npy` fitness vectors.
- `results/smoke/` → the pre-campaign plumbing records (3 pure smokes: dense-numpy / specialized-numpy / dense-iree + one `eval64` regression control + the legacy clean-skip record) and `manifest_smoke.txt`; deliberately **not** manifest ids.
- `CONTEXT.md` → this file.
## Constraints
- Everything here is new-side and additive: `../SPEC.md`, `../REPORT.md`, `../r2/**`, `../new/check_smoke.py` and every existing task's behaviour are untouched; the harness changes are the `eval-pure` registry/flag/dispatch wiring plus `run_pure`.
- One process per config (the compile cache is per-process), warm/steady-state only: construction is timed separately (`compile`), then `--warmup 10`, then 5 timed blocks. `--reps 1 --warmup 0` is not quotable.
- The pure route (`--mode`) and the companion route (`EVOGP_EVAL_MODE`) are set together by the runner; a single-route config would compare two different routes.
- Never present a `local-fallback:*` record as a frozen-API number: `pure.runner_source` + `compile.path` say which constructor ran, and a frozen runner without a graph-call counter is recorded as `n_graph_calls_source: "assumed-1"`.
- `--stage-probe` is accepted but never installed for this task (it would tax the timed loop); `stages` stays `null` and the measurement lives in `pure`/`compile`/`e2e_companion`.
- GPU 6 by default, never GPU 7; medians carry the usual ±10–20 % shared-box band; IREE numbers are only quotable after that round's backend-agreement pre-flight.
- `../../../src/evogp/**` is read-only from here (the harness must never be the thing that changes the engine it measures).

## Notes for Agents
- `results/**` (campaign records, agreement records + `_values.npy`, smoke records) is **immutable evidence**: read it, never edit, regenerate or re-run in place — the write-ups are derived from the records, never the reverse.
- Quote `pure.median_per_invocation_ms` (= one population evaluate); `per_graph_call_ms` is a normalization whose meaning depends on `n_graph_calls_source`, and `local-fallback:*` numbers are the harness' wrappers around the engine's own memo key + shared `etl_engine.CACHE`, not a frozen-API measurement.
- The two `FROZEN-ADAPTER` markers in `../pure_forward.py` (the `build_*_runner(forest, x)` call form + the no-arg `.run()`) are the only places the landed frozen signature may need a one-line adjustment.
- Run everything from the repository root with the project venv (no `python` on `PATH`) and a CUDA-visible device; serialize heavy phases with the single shared `flock` and keep `timeout` inside it.
- The 3-place id sync is `run_pure.sh`'s group arrays + its `config_spec()` case + `manifest.txt`; a new id must be added to all three.
